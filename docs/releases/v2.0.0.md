# v2.0.0: the rebuild

The Hololive OCG Wiki has been rebuilt from the ground up. The site is live at
**[hololive-ocg-wiki.tskrlabs.com](https://hololive-ocg-wiki.tskrlabs.com)**, serving 2,463
cards in seven languages, with a card database, search, filters and a deck builder.

This is the first tagged release of this repository. Everything before it is the rebuild
itself. The version number is 2.0.0 rather than 1.0.0 because there is a v1: a working site
that has been serving readers for a year, at
[`lichingchester/hololive-ocg-wiki`](https://github.com/lichingchester/hololive-ocg-wiki).

## Why rebuild a working site

One bug class.

In v1 the shape of a card was written out by hand in four places: a TypeScript union, a SQL
schema, a JSON fixture and the scraper. They drifted apart, because nothing made them agree.
The visible result was that 24 cards were silently unfilterable in the live UI, since one
union was missing the `HR` rarity and a filter that should have matched them returned
nothing. Nobody reported it. Nothing was broken enough to notice, which is exactly why it
lasted.

v2 defines the card **once**, as pydantic models, and generates the JSON Schema, the
TypeScript types, the enum arrays and the D1 DDL from that definition. The generated output
is committed, and `make check` fails if it is stale. The particular bug above is now
impossible rather than unlikely, and the property generalises: when the official card list
prints something no mapping covers, the build stops and names the value it could not place,
instead of shipping a card that quietly belongs to no category.

That is the whole thesis. Everything below follows from it.

## What it is now

**One Worker, one origin.** Hono and Zod serving the API from D1 and the static site from
an assets binding, with card images on R2 behind a CDN domain. v1 ran a server build and
then shipped only its static output, discarding the server it had just built. v2 makes the
deployable artifact the declared output.

**A pipeline instead of nine numbered scripts.** `holo-data` is one CLI:
`scrape · transform · images · translate · build · verify · publish · seed · status`.

**Translations that cannot disagree with themselves.** The translation cache is
content-addressed, so one source string has one cache slot and two cards printing the same
Japanese cannot render differently. Divergence is not reduced, it is unrepresentable. A full
cold run costs 204 API calls where the old per-card scheme took 14,778.

**Every card has a URL.** 2,463 card pages, each with server-injected metadata via
`HTMLRewriter`, real 404s for bad keys, and a sitemap listing 17,241 URLs across seven
locales.

**Verification is local.** `make check` runs the schema, the pipeline, the seeder, the
TypeScript parity checks, the Worker's unit and endpoint tests and the site's tests.
`make check-site` builds the site twice and asserts what `nuxt generate` actually emitted.
There is no CI in this repo, deliberately.

**A contributor needs no credentials and no Python.** `npm install && make dev` runs the
site and the Worker against 34 committed fixture cards and committed R2 artifacts, chosen
to cover every card type, every rarity, all nine colours, all seven locales and 546 Q&A
items. That property is verified from a scratch clone.

## What changed for readers

- **Every card has its own page**, linkable, bookmarkable and indexable. v1 had no card
  route at all.
- **Set-code filtering.** `hBP03` is a filter dimension with its own URL, and typing one
  into the search box applies it.
- **Tag filters work.** They returned zero cards for every tag, in every language, because
  the published filter options carried `#`-prefixed values against a junction table holding
  unprefixed ones.
- **Searches matching more than 100 cards** returned a 500 instead of results.
- **A rebuilt interface**, with card names on the grid, a density control, a filter rail on
  wide screens, and a deck panel that pushes the grid rather than covering it.
- **The phone stopped losing things.** Data status, GitHub and the Discord invite were
  desktop-only and vanished on a narrow screen with no indication anything was missing.
- **A status page that distinguishes the official card list from our own churn**, so a
  translation pass on our side no longer reads as new cards being printed.

## Known gaps

Both are open issues, both cosmetic, both in translated prose rather than card data:

- Card names inside `「quotes」` in rules text stay Japanese in the other six languages
  ([#27](https://github.com/tskrlabs/hololive-ocg-wiki/issues/27)).
- Some game vocabulary is still inconsistent inside translated prose
  ([#28](https://github.com/tskrlabs/hololive-ocg-wiki/issues/28)).

v1 remains online and is **no longer updated**. New cards, fixes and translation work land
here only.

## Reading the reasoning

Every decision taken during the rebuild is recorded, with the measurements behind it:

- [`docs/v2-plan.md`](../v2-plan.md) for the design
- [`docs/adr/`](../adr/) for eleven ADRs written as the work happened
- [`docs/progress.md`](../progress.md) for the working log, including what went wrong

Those documents are candid about defects found along the way, because the useful part of a
rebuild is not that it shipped but what it turned up. If you are evaluating whether to
contribute, they are the honest version.
