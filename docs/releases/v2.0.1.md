# v2.0.1: analytics that actually record

A patch release. One user-visible fix, plus the pipeline repair that the first card-set
update turned up.

## Analytics recorded nothing for a week

The launch posture ran GA4 with every Consent Mode v2 storage type denied, on the reasoning
that cookieless consent-denied pings would still yield pageviews and geography, and that a
site collecting nothing needs no consent banner. The first half of that was wrong. GA4 uses
those pings only for behavioural modelling, which never activates at this traffic level, so
the property recorded **zero events for the week after launch**.

What made it survive a week is worth recording: the tag fired correctly and `/g/collect`
returned `204` every time. That proves nothing. The endpoint accepts every hit whether or
not it is retained, so the only way to tell was to query the Data and Realtime APIs and find
them empty.

`analytics_storage` is now granted, which sets the `_ga` cookie and a persistent identifier.
The `ad_*` types stay denied, since no ads run here. The collection is disclosed in the
`/about` privacy copy rather than behind a banner.

See [ADR 0011 D1](../adr/0011-launch-posture.md), amended.

## The v2 translation path could not onboard a new card set

Found while taking the card set from 2,463 to 2,559, and fixed there.

`translate-units` collected its work from the built `cards.json`, which is the one artifact
guaranteed **not** to contain a new card set: `build` refuses to write a card whose locales
are missing, so on an update the build on disk is the previous set. The two commands
deadlocked. `build` wanted translations; `translate-units` wanted a build.

The failure was silent in the worst way. `translate-units` reported "everything is up to
date" against the old set, while `build` failed validation on exactly the cards needing the
translations it had just declined to fetch. 132 new units were invisible to it.

It now reads the scrape, which is what `translate` has always done; only the v2 units path
had diverged. Units are collected from `translations.ja`, which `build` passes through
unchanged, verified over the 2,463 shared cards before the switch. The guard is pinned by
sabotage: reverting the call makes the test fail by name.

## Also in this release

- The card set is at **2,559**, up from 2,463, including the new `hEB01` set. Card data
  reaches the site through D1 and R2 rather than through a release, so this was live before
  this tag existed; what the deploy carried was the sitemap.
- A rules notice left the official card list, so `notices.json` is now empty. Both `publish`
  and `/api/notices` already treated that as a normal state.
