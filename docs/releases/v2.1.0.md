# v2.1.0: the reader keeps their place

A minor release. One fix that had been reported against the live site and shipped wrong
once already, a refactor that makes the same class of bug unrepresentable, and a pass over
two surfaces that were noisier than the information in them.

## Closing a card lost your place in the list

Reported against the live site, and the second attempt at it. The first fix was correct
about everything except when it ran.

On remount the card grid's geometry starts as a hardcoded guess for a 1280px viewport,
which a `ResizeObserver` corrects a frame or two later. The scroll restore ran against that
guess, and the trap is that it does not fail: it writes the offset, reads it back, reports
success and consumes the saved position. Then the correction lands, the column count
changes, the scroller's key changes with it, and the list remounts at the top with nothing
left to put it back.

That is why it survived review. The bug appears only where the six-column guess is wrong,
so anyone testing at 1512px or 1600px saw a working feature:

| viewport | measured columns | vs. the guess | outcome |
|---|---|---|---|
| 1280 | 5 | wrong | lost |
| 1512 | 6 | right | kept |
| 1600 | 6 | right | kept |
| 1728 | 7 | wrong | lost |
| 1920 | 8 | wrong | lost |

The restore now waits for the observer to report before spending the memory. Giving up
still clears it, because a stranded memory would silently suppress scroll-to-top on every
later filter change.

Verified over 13 browser combinations: 390, 768, 1280, 1512, 1728 and 1920 px against
Escape, browser Back and the close button.

## The grid's geometry is one value now

The fix above added a flag that sat beside three separate refs a single function happened
to assign one after another, with nothing saying the four belonged together. The
correctness of the restore rested on a convention.

The tempting simplification is worse than it looks. Gating on the column count reads as
equivalent, since that is what the scroller's key carries, but sweeping every plausible
content width shows exactly one that reproduces the guess outright: 1280, the width it was
computed from. Agreeing on columns while disagreeing on row height is the common case, not
a corner, and a restore against the wrong row height is off by whole rows.

The geometry and the claim that it has been measured are now one value, written in one
assignment. A half-measured grid is not a state the component can be in. The three names
survive as read-only computeds, so roughly 20 call sites and the template are untouched,
and the single-writer rule is enforced by the types rather than by asking future readers to
be careful.

## What's New reads as three lists instead of eight labels

The release notes page rendered one coloured badge per entry, so the v2.0.0 notes showed
eight badges carrying three distinct words. Repetition at that density stops reading as a
label and starts reading as decoration.

Entries are grouped by kind now, one badge heading each group, in the order added, changed,
fixed. The consequence worth knowing is that the order entries are written in no longer
reaches the reader, so `content/README.md` now says so: a release that needs a narrative
puts it in the summary, which is prose and is rendered where the author put it.

The badge stays above its entries rather than moving into a left gutter. Grouping would
permit a gutter, since one badge no longer has to align with anything, but the original
argument holds unchanged: the three labels translate to anything from "New" to
"เปลี่ยนแปลง", and across seven locales there is no gutter width to align to.

## GitHub and Discord are in the header on wide screens

Both were in the overflow menu at every width. From `lg` up they sit in the header row
behind a divider, and leave the menu at that width so neither is listed twice.

Only those two, and the reason is measurement rather than taste. Six inline destinations
with labels cost roughly 960px in Spanish against roughly 880px of usable row at 1024px,
and Japanese and Thai are comparable. These two carry a brand mark that identifies itself
without a word, so they are the two that can go icon-only. The other four need their labels
and keep the menu alive at every width.

This makes the header width-conditional again, which the v2.0.0 rework had deliberately
removed, so it is recorded rather than slipped in. The distinction is that the old
behaviour made items unreachable on a phone with nothing indicating they were missing,
while below `lg` the menu still holds all six. Nothing is unreachable at any width; an item
is on the shelf at one width and in the drawer at another. See ADR 0009 D28.

Two details behind it. The Discord link depends on a runtime fetch, which inside a closed
menu is invisible and in the header row would shift every control beside it mid-load, so it
reserves its space instead. And the six header strings were absent from the translation
sweep, present in all seven languages by luck rather than by test; two of them are now the
accessible name of an icon-only button, so all six are covered.

## Also in this release

- A new test asserts every changelog entry survives the regrouping. The failure mode of a
  grouping bug is a dropped release note, which is invisible on a page nobody reads
  closely.
- The release runbook now records how to tell a deploy landed. Confirming v2.0.1 took
  twenty minutes of looking at the wrong thing: chunk filenames repeat across builds and
  are served immutable, a missing chunk returns the SPA fallback with a 200, and page
  components are lazily imported so no crawl of the entry chunk reaches them. The build
  timestamp is the check that works.

- Some game vocabulary is still inconsistent inside translated prose

Opened by this release, both awaiting triage rather than blocking anything:
