# v2.2.0: names that were never on the page

A minor release, and the through-line is worth stating: three of the four fixes here were
filed as cosmetic and turned out to be text a reader could not see at all. Two of them had
been triaged as low priority on that reading, twice.

## 54 character names were invisible on the live site

Filed as issue #27, described there as "purely cosmetic", and triaged as "the milder of the
two defects" in this issue as recently as three weeks ago.

Card rules text refers to other cards in angle brackets. The Japanese source writes those
in CJK brackets, 6,804 times, and never once in ASCII. The translation model sometimes
returned the ASCII form instead, which reads as an equivalent rendering and is not one:
ability text reaches the page through `v-html`, so a browser parses `<Hakui Koyori>` as an
unknown HTML tag and drops it.

The rule then reads:

```
STORED  : Additional ability if attached to 1st or higher <Hakui Koyori>
RENDERED: Additional ability if attached to 1st or higher
```

It tells the reader the ability triggers when attached to nobody. 54 names across 24 card
pages, all English but one.

Normalising to the CJK bracket is the fix, and the direction matters more than it looks:
the opposite normalisation, which reads as equally defensible on a Latin-script page, would
have taken the count of swallowed names from 54 to roughly 1,600.

The renderer is still the underlying hazard and is tracked separately as #80. The data is
clean and a pipeline pass keeps it clean, but the safety currently lives upstream of the
component rather than in it.

## A quoted skill name stayed Japanese while its translation sat one entry away

The other half of #27. Rules text quotes another card's skill or art name in corner
brackets, and the model sometimes left the quote in Japanese while translating the sentence
around it. A card read "If you used your SP Oshi Skill (in Japanese) this game" while the
skill's own entry, in the same cache, already said `Tombol Reset Kehidupan`.

Nothing was looking it up. It does now, on exact match only, which also repairs the cases
where masking restored the character name but not the art title around it.

855 substitutions. The remaining occurrences are quotations of rule text that is not itself
a translatable unit, so there is no canonical answer to substitute.

## The dual-colour icon, fixed by deleting it

Issue #22: one of the nine colour symbols was 88x108 where the other eight are 330x410, so
it rendered visibly soft. The official site publishes it that way, so this was not a
conversion loss on our side.

Both options in the issue were unattractive. Redrawing the asset means shipping our own art
in place of official art, and the badges overlap at an offset a naive composite would not
reproduce. Upscaling is the same question asked more quietly.

The card itself settles it. All three dual-colour forms print two separate badges on a gold
ribbon, and the source spells that two different ways for no reason we control: one token
for some cards, two tags for others. Normalising them to a colour pair at extraction means
two full-size badges render, and the low-resolution asset is not needed by anything. The
file is deleted rather than replaced.

The combination keeps its name. A dual-colour card reads "Blue-Red" rather than "Blue, Red",
because that is a colour identity the game names, and the stored order stays the printed
order: FUWAMOCO prints blue then red, miComet red then blue.

This deleted more code than it added. A colour filter previously had to be widened at query
time so that filtering for blue would also match the fused code, and the filter UI had to
exclude those codes from its checkboxes. A card that holds one row per badge needs neither.

## Thai rules answers that were shipping as Japanese

Issue #28 recorded one game term rendered three ways in Thai. Measuring the corpus found
something worse behind it: 17 Thai rules answers were shipping as untranslated Japanese
sentences, and 61 percent of Thai Q and A entries carried Japanese fragments mid-sentence.

That corpus was migrated rather than re-translated during the translation rework, under a
prompt that predates the name-masking the rest of the text now goes through. It has been
re-translated: 608 units, and the result is 15 percent carrying fragments, down from 61,
with no wholly untranslated answers left.

The remaining five locales are #81 and are deliberately left for the maintainer to trigger,
because each one costs API budget.

## Returning from a card kept your place, but only sometimes

Issue #59, fixed before v2.1.0 shipped and merged after it, so it has been live and
unannounced. Opening a card and closing it again appended pages correctly but discarded
them on the way back in some paths. It is in these notes for completeness rather than as
news.

## For contributors

**A bad translation is now a pull request.** `pipeline/corrections/{locale}.json` is
committed, and an entry names the Japanese source string and what it should say. The cache
folds it in and holds it back out on save, so a correction lives in exactly one place and
deleting it actually removes it. This closes #18, which had been open since July with the
honest note in CONTRIBUTING that a translation fix could only be reported, never sent.

You do not need a Python toolchain, an API key, or the card data to write one.

**`holo-data evict`** drops cache entries so a re-translation will redo them. A migrated
entry is a fresh entry as far as the pipeline is concerned, which is correct and is also
why re-doing one has to be deliberate. It refuses to touch a human decision.

## Known gaps

**`normalise-cache` is now a required step after every translation run**, not a cleanup you
reach for occasionally. The Thai re-translation produced 608 brand-new units and the model
reproduced all four spellings of the term in them, 93 occurrences of the worst one. A
translation run refills these defects rather than retiring them. The command line prints
this after every run, but it is a workflow rule that lives in a person's head and could be
skipped.

**The `v-html` render path is unchanged** (#80). Nothing puts ASCII angle brackets into
ability text today, and the pipeline pass keeps it that way, but the component would still
swallow them if something did.

**Five locales still hold migrated Q and A** at between 9 and 52 percent carrying Japanese
fragments (#81).

**The colour contract dropped two enum values.** `blue_red` and `white_green` are no longer
`ColorCode` members. The package is workspace-only and has no external consumers, which is
why this is a minor release, but a fork or a local branch reading those values will need
updating.
