# v2.4.0: the oshi stage skill

A minor release with one subject: a part of the card the official list has printed since
hBP07, and this site never showed.

## The official list added a third skill, and extraction dropped it

Oshi cards from hBP07 onwards carry a 推しステージスキル (Oshi Stage Skill): a passive
skill, always active while the oshi is on stage, printed above the oshi skill. The card
page marks it up as `div.stage.skill`, beside the `div.oshi.skill` and `div.sp.skill` the
extractor already read.

The extractor only reads the classes it names, so the new block was dropped without a
word. Nothing failed and no field was empty; the skill simply was not there. It went
unnoticed for three sets, until a player compared a card against the official page. In
total: 16 skills on 51 printings, across hBP07, hBP08, hBP09 and hEB01.

## Its own model, because most have no timing

The stage skill flows end to end as `oshi_stage_skill`: extraction, the contract, both
`localize()` implementations, translation, the D1 payload, search, and the card page.

It is a new `OshiStageSkill` model rather than a reuse of `OshiSkill`, for one reason:
`OshiSkill.timing_code` is required, and 34 of the 51 stage skills print no timing
bracket. Reusing the model would have made those unrepresentable, and `localize()` only
emits a skill the card says it has, so they would have been translated, stored, and never
shown. On the stage skill, `timing_code` is optional.

Translation reuses the existing `skill_name` and `skill_effect` kinds, so a stage skill is
prompted and cached exactly like an oshi skill. The first pass was 192 units across 6
locales, translated from the Japanese, for 19,354 tokens. Seven names were corrected by
hand in `pipeline/corrections/`: three English casing and wording fixes, and four Spanish
names, three of which were already English and kept as such in every other locale.

Search indexes the stage skill's name and effect, so searching `WORLD DOMINATION` or
`ドドドライブ` finds the oshi that prints it.

## Unknown skill blocks now stop extraction

So that the next new block cannot repeat this, extraction raises `UnknownSkillBlock` on
any `div.skill` it does not read, naming the class and the label the site printed. This is
the same stance the pipeline already takes on an unmapped enum: a card we cannot fully read
should not ship unannounced.

There were no extraction tests before this release. `pipeline/tests/test_extract.py` adds
them, on real card markup.

## Known gaps

**The oshi skill's holo power cost has never been extracted** ([#90]). The regex expects a
full-width colon and the site prints an ASCII one. The contract's note that "no card has
ever carried a cost" is true because of the regex, not the data. Fixing it changes every
oshi card's payload, so it is its own change.

**Translation coverage can report 100% with a nested field missing** ([#91]). Before the
stage skill names were translated, `build` passed 37 of the 51 printings with the skill
absent outside Japanese, because coverage counts cards rather than fields. It was caught by
checking all 51 directly, not by the coverage line.
